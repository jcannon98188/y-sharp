# y-sharp

A pure C# port of [Yjs](https://github.com/yjs/yjs) v13, the CRDT library for building collaborative applications.

> **Status: in active development. Not usable yet.**
> The verification suite is complete and the implementation is being built on top of it, one spec at a time. The foundations (feature gates, source layout, lib0 encoding, `YValue` and the JS-compatible JSON layer, the object-per-item store) have landed. Documents, transactions, the update codecs, the shared types and the protocols have not. Most public members still throw `NotImplementedException`, and the public API may change. Do not depend on it yet.

## What it is

y-sharp aims to be a drop-in .NET peer for Yjs. A y-sharp document and a Yjs document should exchange updates, state vectors and sync messages and converge on the same state.

- **Pure managed C#** (net10.0). No native core and no FFI (ADR 0004).
- **Wire-compatible with Yjs v13.6.33**, lib0 v0.2.99 and y-protocols v1.0.7. These are pinned as git submodules and act as the oracle. Yjs v14 is out of scope.
- **Match JS by default.** Yjs quirks are reproduced unless doing so is unsafe, and each deliberate divergence is a recorded decision with a test that shows the JS behaviour (ADR 0003).
- **Planned scope:** the V1 and V2 update formats; `YText`, `YArray`, `YMap` and the XML types; events and observers; snapshots; relative positions; the undo manager; subdocuments; permanent user data; and the awareness, sync and auth protocols.
- **Designed for memory.** Allocation budgets for named hot paths and a memory-layout spike gate are part of the plan (ADR 0009, 0018, 0023).

## How correctness is tested

Interop is the core requirement, so the test suite was designed and built before the implementation. Tests were laid out against the real Yjs first, and the library is being built to turn them green. A test whose feature has not landed is skipped, not failed, and the skip count falls to zero at release.

- **Behaviour registry and traceability.** Every behaviour is an entry in a YAML registry under `docs/inventory/`, traced to the Yjs source line it comes from. Tests carry tags (`[Covers]`, `[PortOf]`, `[Diverges]`). A gating test fails the build if an active behaviour has no covering test, an ID is reused or unknown, or a declared divergence has no test. All 209 upstream Yjs tests are accounted for as ported, merged, replaced by fixtures, or skipped with a reason (ADR 0010).
- **Golden fixtures from the real Yjs.** About 140 committed fixtures are generated by replaying declarative operation scripts on the pinned Yjs, and record exact update bytes, state vectors and document dumps. A CI job regenerates them all and fails on any byte of drift (ADR 0011).
- **Live differential testing.** FsCheck generates operation scripts, and both Yjs (in a Node child process) and y-sharp run them. Bytes must match exactly, and convergence is checked under shuffled, duplicated and dropped delivery. Failures shrink to a minimal script and are saved as fixture candidates. A failing seed is a real bug and is never retried or quarantined (ADR 0012).
- **Ports of the upstream randomized tests.** The lib0 PRNG is ported bit-exact so upstream seeds reproduce, and the JS simulation tests are replayed from recorded operation logs (ADR 0015, 0017).
- **Hostile-input and fuzz testing.** Nine named attack classes cover truncation, mutation, oversized lengths, deep nesting, clock abuse, bad references, amplification and protocol abuse. After every hostile input the document must not be faulted and must still encode and accept a good update. Runs are bounded by timeouts and allocation limits. Nightly runs add SharpFuzz and a deep-recursion canary process (ADR 0013).
- **Error model and concurrency.** A crash-safety contract (limits, a faulted-document state, no unbounded recursion) and a thread-safety contract are each tested, including with a schedule-exploring scheduler and stress and soak runs (ADR 0005, 0006).
- **Memory budgets.** Allocation tests assert bytes per operation, and a slow tier checks bytes per item against the Yjs figures. The storage model was chosen by a measured spike (ADR 0018, 0023).
- **Feature gates.** Tests declare the feature they need (`[Requires(...)]`), so the suite stays green as features land. Changes to existing tests during implementation follow strict rules (ADR 0020, 0022).

CI runs on GitHub Actions: gating on Linux, Windows and macOS; fixture drift; a differential smoke job; and a nightly tier for the slow differential, fuzz, soak, memory and benchmark runs.

## Building and testing

```bash
git clone --recurse-submodules https://github.com/jcannon98188/y-sharp.git
cd y-sharp
dotnet build YSharp.slnx
dotnet test --solution YSharp.slnx
```

This runs the gating tier and needs no Node. The live differential tests need Node (see `.nvmrc`) and `npm ci` in `tools/fixture-gen`, and run with `YSHARP_TIER=Smoke` or `YSHARP_TIER=Nightly`. Re-run one saved failing script with `YSHARP_REPLAY=<path>`.
