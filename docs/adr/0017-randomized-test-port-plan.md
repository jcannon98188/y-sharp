# Randomized JS tests are ported with fixed seed lists, time-boxed nightly runs and 12 golden op logs

Extends ADR 0010, 0011, 0012 and 0015. About 100 upstream tests build documents through the multi-client simulation; 48 are time-repeated `testRepeat*` tests (`docs/research/js-tests.md` sections 2.3 and 5). Upstream repeats until 50 ms have passed, so run counts and seeds vary from run to run. The gating tier cannot do that (ADR 0006: a failing seed is a real bug, never retried or quarantined).

- **Gating: fixed seed lists by size class.** Each `testRepeat*` runs a committed seed list `1..N` through the bit-exact PRNG (ADR 0015), where N depends on the test's upstream operation count: up to 100 operations, N = 200; 101 to 600, N = 40; 601 to 1800, N = 10. Operation counts stay as upstream (`testRepeatGeneratingYmapTests10` keeps its actual 3, noted in the ledger). Upstream's `--production` sizes (above 1800 operations) are not gating. One test per upstream test and size, one xUnit data row per seed, so a failure names the seed. The classes and N are calibrated at spec time so the randomized gating total stays under about 60 seconds on the Linux Release job; if it does not, N falls within a class and the boundaries stay.
- **Regression seeds.** Any nightly failure adds its seed to `tests/YSharp.Tests/Simulation/regression-seeds.json` (test id, seed, reason), run in gating forever after. `YSHARP_SEED=<n>` with the usual test filter pins one seed locally, like upstream's `--seed`.
- **Nightly: random seeds, time-boxed.** Each randomized test also runs with fresh seeds for about 10 seconds (upstream's `--repetition-time 10000`), minimum one run, and the production-only sizes (3000, 5000, 10000, 30000 and 100000 operations) run as their own `Nightly` tests with the same box. The start seed is logged; a failure prints the seed and saves the expanded op log as a fixture candidate with a `repro` header (ADR 0012). The randomized nightly work shares the nightly job's 20-minute budget with the differential and fuzz tiers; the per-test box shrinks if the total would overrun, and the shrink is reported.
- **`2Repeat`.** `testRepeatGenerateQuillChanges2Repeat` loops 1000 times inside the test. The port treats each inner iteration as a seed of the Quill-2 test: they are subsumed by the seed lists and the nightly box, and the ledger records it as `merged-into`.
- **`testInsertAndDeleteAtRandomPositions`.** Upstream asserts nothing (its mirror string is commented out). The port restores the mirror check: a gating variant of 2000 operations over 10 seeds, and the upstream 100000 operations as a nightly test.
- **Golden op-log fixtures: four generators, three sizes.** The map, array, text (`textChanges`) and quill (`qChanges`) generators each get a small, medium and large run at seed 1, 12 fixtures under `fixtures/sim/<generator>-<size>.json`. Sizes: map and array 40, 300 and 1800 operations; text and quill 30, 100 and 300. Each records the expanded op log, the delivery schedule, and the `updates`, `state` (V1 and V2), `sv`, `doc`, `structs` and `ds` observations (ADR 0011). They are the gating guard against wrong-but-convergent conflict order. Seed 1 is in every gating list, so the fixture replays the same run the seed list exercises. The other 36 or so Repeat tests have no fixtures; the live differential covers larger generated runs.
- **Draw parity is checked.** The Node generator module for these fixtures is a hand-written copy of the four generators on the pinned lib0 `prng`, emitting ops JSON. A gating test runs the C# generator at seed 1 for each fixture and requires the expanded op log to be identical. That proves the PRNG, the draw order and the generators match, and is the only place the draw sequence is asserted.
- **Faithfulness: keep draws, fix defects.** The draw sequence matches upstream so seeds replay. The defects in research section 6.7 are fixed and recorded as simulation divergences, `SIM-01` to `SIM-05`, each with a `[Diverges]` test or comment naming the upstream behaviour:
  - `SIM-01`: `checkResult` compares each replica with itself upstream; the port compares different replicas.
  - `SIM-02`: `compare` asserts `equalDeleteSets`; upstream discards the result.
  - `SIM-03`: the quill code-block operation uses the key `attributes`; upstream passes `format`, which `applyDelta` ignores.
  - `SIM-04`: the one coin-flip draw in `init` selects V1 or V2 for the whole run and the run really uses it. Upstream falls back to V1 in both branches. Because y-protocols has no V2 sync messages, V2 runs use a test-only framing with the same message-type numbers and a V2 payload, and `compare`'s merge oracle uses `mergeUpdatesV2`. This is TestKit framing, not a y-protocols claim.
  - `SIM-05`: payload counters (`_uniqueNumber`, `charCounter`) reset for every run instead of leaking between tests, so a seed alone reproduces payload text. The Node generator does the same.
- **Ledger and registry.** The 48 Repeat tests are `ported` (2Repeat is `merged-into`); `testInsertAndDeleteAtRandomPositions` is `ported` with its restored assertion. The sim harness itself (`TestConnector`, `init`, `compare`, `applyRandomTests`) is registry entries `SIM-10` and up, `y-sharp-own`, `layers: [unit]`, and the draw-parity and fixture tests carry `[Covers]` for them.
