# Match JS behaviour by default

Interop is the core requirement, so y-sharp matches Yjs quirks unless doing so is unsafe. Each deliberate divergence is a recorded decision plus a tagged test that shows the JS behaviour. Behaviour that crashes or recurses without bound always diverges.

Recorded divergences are listed beside the tests that carry `[Diverges]`. One that shapes the API: client ids are `ulong` and accepted up to 2^53-1 (the lib0 limit, ADR 0008); a client id above 2^53-1 on the wire is Malformed, where JS silently rounds it to the nearest double (Q12, ENC-37).

Clocks and lengths (Q22): JS holds them as doubles; y-sharp holds clocks and lengths as `long` and finds structs by a plain binary search. Below 2^53 this is observably identical. On the wire a clock, a length or a clock plus a length that is negative, non-integer or above 2^53-1 is Malformed, where JS rounds silently. Varuint fields cannot be negative or fractional, so in practice this rejects 2^53 and above, the sum of a start clock and a length above 2^53-1 (struct ranges and delete-set ranges), and a negative clock produced by a V2 diff column. Tests: `Q22_*` in `MalformedInputTests`.

Zero-length delete ranges (ENC-51, ADR 0005; ratified as ignored in TASK-4.14, reversed by the owner in TASK-17.2 on 2026-10-27): y-sharp rejects an update holding a delete range of length 0 as Malformed, in every decode path (apply, validate, convert, merge and the other update functions). Yjs never writes such a range. It accepts one when its client is already known and the range starts below the client's state, but throws `Unexpected case` when the range has to be parked as pending state (the V2 delete-set writer asserts a length above 0) and when the update is converted to V2. Ignoring the range, as y-sharp did before, made a y-sharp peer accept and relay an update a Yjs peer then rejected (found in a host integration). V2 cannot carry such a range: its length column holds the length minus 1. Snapshots and PermanentUserData entries keep reading a range of length 0 as Yjs does, since they are not updates. Tests: `Enc51_*` in `MalformedInputTests`; the fixture cases `delete-set-len-0*` in `hostile/malformed-codec-extras.json` are classified `diverge` with divergence `ENC-51`; the live differential's `zero-length-delete-range` normaliser.

Out-of-order pending delete ranges (ENC-86, TASK-4.28, owner sign-off pending): Yjs parks delete ranges it cannot apply yet by re-encoding them as V2. When one client's ranges arrive out of order, the V2 writer writes a negative clock difference, which lib0 writes as one garbage byte, so the parked ranges and every later state encode are wrong. y-sharp keeps the ranges as sent. Both accept the update and the content matches; only the re-exported delete set differs. Reproducing the corruption would mean emitting ranges no peer sent, so y-sharp does not. Tests: `Enc86_*` in `MalformedInputTests`; the fixture case `delete-set-pending-out-of-order` in `hostile/malformed-codec-extras.json` is classified `diverge` with divergence `ENC-86`; the live differential claims it with `UnsortedPendingDeleteSetNormaliser`.

An item ending at clock 2^53 (Q22, TASK-4.42, owner sign-off pending): an item's last id may be 2^53-1, so an item there decodes and may wait for its predecessors (ENC-36, ENC-71). Once its predecessors are known, y-sharp rejects an item whose clock plus length is above 2^53-1, with the rest of its client's structs in that update (STR-71 style), where Yjs integrates it. The state vector and the item's delete range would end at 2^53 and would not decode again under Q22. Tests: `ItemAt2Pow53Minus1_*` in `MalformedInputTests`; the hostile corpus case `clock-plus-deleted-length-reaches-2-pow-53` in `hostile/hos-clock.json`.

Format and embed values V1 JSON cannot hold (ENC-87, ADR 0005, TASK-4.42, owner sign-off pending): V2 carries a format or embed value as Any, so it can hold a BigInt or a top-level undefined. Yjs stores either, then every V1 encode of the document throws. y-sharp rejects such an update as Malformed, and `YText` rejects such attribute values with `ArgumentException` (embeds already were). A document therefore always encodes in V1 and V2. Tests: `Enc87_*` in `MalformedInputTests`, `FormatValues_ThatV1JsonCannotHold_*` in `TextTests`; the fixture cases `v2-format-value-bigint` and `v2-format-value-undefined` in `hostile/malformed-codec-extras.json` are classified `diverge` with divergence `ENC-87`.

Items of length 0 (ENC-88, ADR 0005, TASK-4.43, approved by the owner on 2026-10-26): an item of `""` text, Deleted 0 or an empty JSON or Any list owns no clock. Yjs stores it; when it is pending, the merged state encode drops it, so a struct that waited behind it no longer waits, and the document's own state may then be rejected on re-apply (found by SharpFuzz). Yjs never writes such an item, because inserting `""` or `[]` is skipped. y-sharp rejects the update as Malformed. GC and Skip structs of length 0 are still accepted. Tests: `Enc88_*` in `MalformedInputTests`; fixture cases `item-zero-length-*` in `hostile/malformed-codec-extras.json` (diverge ENC-88) and `zero-length-item-releases-a-waiting-struct` in `hostile/hos-clock.json`; the live differential's `zero-length-item` normaliser.
