# The live differential harness runs stateless ops scripts against one Node child

Extends ADR 0001, 0003, 0010 and 0011. The harness is the only layer where y-sharp's bytes meet live Yjs; golden fixtures cover fixed inputs, this covers generated ones.

- **Model.** The request is a whole ops script (ADR 0011 vocabulary); Node replays it on fresh docs and returns the named observations, and y-sharp replays the same script. The only extra step kind is `applyForeign`: apply bytes y-sharp produced to a Node doc. Delivery schedules (order, duplicates, drops) are part of the script, so both sides replay the same one. Every failing script can be saved as a fixture.
- **Process.** One long-lived Node child per test run, started by an xUnit v3 assembly fixture. Requests carry ids, so a pool can be added later without changing the protocol. Node and submodule versions are verified at startup against `.nvmrc` and the fixture headers.
- **Protocol.** Newline-delimited JSON on stdin/stdout using the ADR 0011 tagged values, bytes as hex, with a schema handshake. Node's `console` is redirected to stderr, which goes to the test log.
- **Compared.** Equivalence of observations (bytes exact, state structural); y-sharp to Node and Node to y-sharp; convergence under shuffled, duplicated and delayed delivery, comparing final and pending state across N replicas on each side; for mutated valid updates, the outcome class (both accept with equal state, both reject, or y-sharp rejects where JS crashes, a recorded divergence). Raw-byte crash fuzzing stays in `YSharp.Fuzz.Tests`.
- **Generation.** FsCheck on the C# side generates and shrinks scripts; Node only executes. The default generator avoids known divergences, so a mismatch is always a bug. A separate divergence-targeting generator applies a per-divergence-ID normaliser and asserts the documented difference exactly.
- **Time.** The Node interpreter installs a virtual clock before importing any pinned code. lib0 binds `getUnixTime = Date.now` at load, so patching afterwards has no effect. It also replaces `setTimeout`/`setInterval`; `tick(ms)` drives that clock and y-sharp's injectable one. An area that cannot be controlled this way stays with fixtures.
- **Hangs.** A per-request timeout on Node kills and restarts the child and fails the case with its script. A separate per-case timeout on a y-sharp worker thread reports a y-sharp hang as y-sharp's fault. A wall-clock cap ends a runaway run and reports the seeds covered. An oracle crash or hang on a generated script is `oracle-misbehaved`: counted, saved and surfaced, not a failure; y-sharp hanging or crashing on it is.
- **Reporting.** A failure prints the seed, the shrunk script, both observation sets and the first difference (byte offset, or a path into the `doc`/`structs` dump). It also writes a fixture candidate with a `repro` header to the CI artifacts directory. `YSHARP_REPLAY=<path>` re-runs one saved script with no FsCheck or regeneration. A failing seed is a real bug: no retry, no quarantine (ADR 0006).
- **Availability.** Missing or wrong Node skips locally with a visible reason and warns on version mismatch. In the differential CI job both are hard failures.
- **Tiers.** The harness lives in `YSharp.Interop.Tests`. A smoke tier with fixed seeds (about a minute) runs as a separate PR job, non-gating at first and promoted once stable. A slow tier with random seeds and a time box (about 20 minutes) runs nightly, uploads failing scripts and fails the job. The normal gating suite stays fixtures only.
- **Areas.** Core types with V1/V2, merge, diff and state vectors, plus y-protocols sync and awareness, from the start. Snapshots, relative positions, subdocs, UndoManager and PermanentUserData join as their ops vocabulary lands; areas register step kinds and observations without touching the harness core.
