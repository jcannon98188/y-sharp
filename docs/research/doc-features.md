# Doc-level features inventory (TASK-1.4)

Oracle: Yjs v13.6.33 (`yjs/src`). Every claim cites `file:line` in that tree; paths are relative to `yjs/src/` unless they start with `tests/`. "Test:" names an existing oracle test that already covers the behaviour (useful as a fixture seed). "Inferred" marks conclusions read off the code that no oracle test exercises. Per ADR 0003, quirks are matched unless unsafe; candidates for divergence are tagged **[DIVERGENCE?]**.

IDs are provisional and stable for the behaviour inventory: `DOC-`, `SUB-`, `UM-`, `SNAP-`, `RP-`, `PUD-`, `GC-`.

## 1. Doc (`utils/Doc.js`)

- **DOC-01 Constructor defaults.** `gc=true`, `gcFilter=()=>true`, `guid=uuidv4()`, `collectionid=null`, `meta=null`, `autoLoad=false`, `shouldLoad=true`; `clientID` = random uint32; `share` empty map; `subdocs` empty set; `isLoaded/isSynced/isDestroyed=false` (Doc.js:60-107). Note `shouldLoad` defaults true for a root doc but ContentDoc-created docs get `opts.shouldLoad || opts.autoLoad || false` (structs/ContentDoc.js:11).
- **DOC-02 Client id.** `generateNewClientId = random.uint32` (Doc.js:23). Range is 0..2^32-1; C# port needs unsigned 32-bit (or long) and must write it as varuint.
- **DOC-03 `get(name, Ctor)` idempotence.** Repeated calls return the same instance (Doc.js:216, `map.setIfUndefined`); it is also in `share` (Doc.js:196). Test: doc.tests.js `testGetTypeEmptyId`.
- **DOC-04 Generic-to-concrete promotion.** `get(name)` with no constructor yields a bare `AbstractType`. A later `get(name, YText)` builds a new `YText`, moves `_map`, `_start`, `_length`, re-parents every item (`n.parent = t` along `_map` chains via `.left` and along `_start` via `.right`), replaces `share[name]`, calls `_integrate` (Doc.js:222-241). This is also how a decoded update that references root type `name` becomes typed. Edge: `_searchMarker` is not carried over.
- **DOC-05 Conflicting constructor.** Existing concrete type requested with a different constructor throws `Type with the name ${name} has already been defined with a different constructor` (Doc.js:243). Requesting `AbstractType` on an existing typed entry returns it (Doc.js:223).
- **DOC-06 Typed getters.** `getArray/getText/getMap/getXmlElement/getXmlFragment` default name `''` (Doc.js:256-299). Empty-string name is a valid, distinct key. Test: `testGetTypeEmptyId`.
- **DOC-07 `toJSON()`** (deprecated) iterates `share` and calls each value's `toJSON`; undefined root types are absent (Doc.js:309-320). Test: `testToJSON`.
- **DOC-08 `transact(f, origin=null)`** delegates to `transact` (Doc.js:184, utils/Transaction.js:415). Nested calls reuse the open transaction and ignore the inner `origin` (Transaction.js:422). Test: `testOriginInTransaction`.
- **DOC-09 Transaction event order** per top-level transaction: `beforeAllTransactions` (only when cleanup queue was empty, Transaction.js:426), `beforeTransaction`, user fn, then cleanup: `beforeObserverCalls`, type observers, deep observers, `afterTransaction`, YText formatting cleanup, then in `finally` GC+merge, `afterTransactionCleanup`, `update`, `updateV2`, `subdocs`, and `afterAllTransactions` after the last queued transaction (Transaction.js:260-402). Edge: observers that open new transactions are queued, not nested; they run after the current one's cleanup (Transaction.js:394-399). Test: `testAfterTransactionRecursion`, `testOriginInTransaction` (origins `first, cleanup, nested`).
- **DOC-10 `update`/`updateV2` emitted only if there are listeners and content.** `doc._observers.has('update')` gates encoding (Transaction.js:366, 373); no event if beforeState==afterState and deleteSet empty (Transaction.js:131). Args are `(bytes, origin, doc, transaction)`. Each event encodes separately, so V1 and V2 bytes are both byte-comparable against the oracle.
- **DOC-11 Clientid collision recovery.** After a non-local transaction that advanced our own client's clock, `clientID` is regenerated (Transaction.js:360-363). Test: `testClientIdDuplicateChange`. Needs an injectable RNG in the port to be testable deterministically.
- **DOC-12 `load()`** is idempotent; on a subdoc with `shouldLoad=false` it runs `transact(parentDoc, tr => tr.subdocsLoaded.add(this), null, true)` and then sets `shouldLoad=true`; on a root doc it only sets the flag (Doc.js:153-161). Test: `testSubdoc` (`doc.load()` "doesn't do anything").
- **DOC-13 `isLoaded` / `whenLoaded`.** Set on the `load` event; promise resolves with the doc (Doc.js:111-116). Test: `testLoadDocsEvent`. Note `isLoaded` is only flipped by listening to `load`; nothing in the library emits `load` except the `sync` handler (DOC-14).
- **DOC-14 `sync` event.** `isSynced = (arg === undefined || arg === true)`; if synced and not loaded, emits `load` (Doc.js:129-137). A `sync(false)` while synced replaces `whenSynced` with a fresh promise (Doc.js:130-132). `whenSynced` resolves on `sync` with undefined/true, then unsubscribes (Doc.js:117-127). Test: `testSyncDocsEvent` (also covers the recreate-on-false path, tests/doc.tests.js:293-340).
- **DOC-15 `destroy()`** order: `isDestroyed=true`; destroy all subdocs (copy of set first); if subdoc: detach `_item`, build a replacement `Doc({guid, ...content.opts, shouldLoad:false})` stored in `content.doc`, and in a transaction add replacement to `subdocsAdded` (unless item deleted) and `this` to `subdocsRemoved`; emit deprecated `destroyed [true]`, then `destroy [this]`; then ObservableV2.destroy (Doc.js:325-346). Edge: the replacement doc has a fresh random clientID until the `subdocs` cleanup assigns the parent's (Transaction.js:383).
- **DOC-16 `getSubdocs()` / `getSubdocGuids()`** return the live set / a new set of guids (Doc.js:163-169). Duplicate guids collapse in the guid set (see SUB-07).
- **DOC-17 `meta`, `collectionid`.** `meta` is only persisted for subdocs via ContentDoc opts (ContentDoc.js:39). `collectionid` is inherited from the parent only if the subdoc's is null/undefined (Transaction.js:384-386; `== null` so undefined also counts).
- **DOC-18 ObservableV2 contract** (lib0). `on/once/off/emit` semantics, `emit` copying listener array, `destroy` clearing observers are inherited from lib0 and belong to the lib0 inventory, but Doc's event names and argument shapes (`DocEvents`, Doc.js:36-50) are part of the public API contract for TASK-1.14.

## 2. Subdocuments (`structs/ContentDoc.js`, `utils/Transaction.js`, `utils/Doc.js`)

- **SUB-01 Content ref 9; wire format** is `writeString(guid)` + `writeAny(opts)` (ContentDoc.js:121-124, 129-131). Length 1, countable, not splittable (`splice` throws `methodUnimplemented`, ContentDoc.js:76-78), never merges (ContentDoc.js:84-86). A split attempt cannot occur in practice because length is 1, but port must not crash on `mergeWith`.
- **SUB-02 Opts serialization.** Only non-default flags are written: `gc:false` if `!doc.gc`, `autoLoad:true`, `meta` if non-null (ContentDoc.js:33-41). `shouldLoad` is NOT serialized; `collectionid` is NOT serialized. `gcFilter` is lost. Wire bytes depend on key insertion order `gc, autoLoad, meta` in the `Any` map: assert byte equality against oracle fixtures.
- **SUB-03 Remote decode** creates `new Doc({guid, ...opts, shouldLoad: opts.shouldLoad || opts.autoLoad || false})` (ContentDoc.js:11, 140). So a remote subdoc has `shouldLoad=false` unless `autoLoad`. Test: `testSubdocLoadEdgeCases` (subdoc3.shouldLoad false), `...Autoload` (loaded in event).
- **SUB-04 Integration.** `content.integrate` sets `doc._item = item`, adds to `subdocsAdded`, and to `subdocsLoaded` if `doc.shouldLoad` (ContentDoc.js:92-99). A local `new Doc()` has `shouldLoad=true`, hence `[added, loaded]`. Test: `testSubdoc` first event `[['a'],[],['a']]`.
- **SUB-05 Re-use warning.** Constructing ContentDoc with a doc already having `_item` calls `console.error('This document was already integrated as a sub-document...')` (ContentDoc.js:21-23). Observable behaviour is log only; do not throw.
- **SUB-06 `subdocs` event** fires in cleanup, after `update` events, only if any of the three sets is non-empty; first adds to `doc.subdocs` and sets `subdoc.clientID = doc.clientID` and collectionid, then removes, then emits `{loaded, added, removed}, doc, transaction`; then destroys each removed subdoc (Transaction.js:380-392). So subdoc clientID tracks parent at add time (SUB: clientID equality check is testable).
- **SUB-07 Same guid, multiple items.** The same guid may appear at several positions/keys; each gets its own `Doc` instance; `getSubdocGuids` dedupes. Test: `testSubdoc` (`['a','a','c']` added on remote, guids `['a','c']`).
- **SUB-08 Delete.** `ContentDoc.delete`: if doc is in `subdocsAdded` of the same transaction it is removed from there (add+delete cancel; no event content), else added to `subdocsRemoved` (ContentDoc.js:104-110). Edge: in `testSubdoc` the remote doc holds two items with guid `a` (keys `a` and `b`), so after deleting key `a` the event reports `removed=['a']` yet `getSubdocGuids()` still lists `a` and `c`. Test: `testSubdoc` last assertions.
- **SUB-09 `gc(store)` on ContentDoc is a no-op** (ContentDoc.js:115): subdoc items, once deleted, become `ContentDeleted` via Item.gc but the Doc instance is destroyed by the `subdocsRemoved` path.
- **SUB-10 Copy** (used by undo/redo, `redoItem` → `content.copy()`, Item.js:239) makes `new ContentDoc(createDocFromOpts(guid, opts))`: a brand-new Doc with same guid and options, `shouldLoad` derived from autoLoad. Test: `testSubdocsUndo` (undo then redo leaves length 1).
- **SUB-11 `destroy()` on a subdoc resurrects a fresh instance** that is reported as `added` but not `loaded`; calling `load()` then reports it as `loaded` only (Doc.js:332-340). Test: `testSubdocLoadEdgeCases`, `...Autoload`; assertion `subdoc1 !== subdoc2`.
- **SUB-12 `destroy()` on a deleted subdoc's item** does not add the replacement to `subdocsAdded` (`if (!item.deleted)`, Doc.js:335-337). Inferred; no oracle test.
- **SUB-13 Parent destroy cascades** to all subdocs (Doc.js:327).
- **SUB-14 Subdoc type content is independent.** A subdoc's own `share`/`store` is not part of parent updates; parent update only carries guid+opts. Port must keep `Doc` instances separate with separate StructStores (inferred from ContentDoc.write, ContentDoc.js:121).

## 3. UndoManager (`utils/UndoManager.js`)

Constructor options and defaults (UndoManager.js:165-172): `captureTimeout=500`, `captureTransaction=()=>true`, `deleteFilter=()=>true`, `trackedOrigins=new Set([null])`, `ignoreRemoteMapChanges=false`, `doc` derived (array -> `typeScope[0].doc`, Doc -> itself, else `typeScope.doc`).

- **UM-01 Tracked origins.** The passed `trackedOrigins` Set is mutated: `add(this)` (UndoManager.js:181); `destroy` removes it (UndoManager.js:395). A transaction is captured iff `trackedOrigins.has(origin)` or `origin?.constructor` is in the set (UndoManager.js:216). Because `null` is tracked by default, `applyUpdate(doc, u)` with no origin (origin null) and any other null-origin transaction IS captured, including remote ones. Test: `testTrackClass`, `testUndoText`.
- **UM-02 Scope filter.** Captured only if `captureTransaction(tr)` true AND some scope entry is `tr.doc`, or in `tr.changedParentTypes` (UndoManager.js:213-217). `tr.changedParentTypes` includes ancestors of changed types, so a change to a nested map counts for an ancestor scope. Test: `testTypeScope`, `testEmptyTypeScope`, `testGlobalScope`.
- **UM-03 Capture merging.** If `lastChange>0 && now - lastChange < captureTimeout && stack.length>0 && !undoing && !redoing` the new change merges into the top stack item: `deletions=mergeDeleteSets`, `insertions=mergeDeleteSets` (UndoManager.js:239-243); else push new `StackItem` (UndoManager.js:246). `lastChange` is only updated for plain user changes (UndoManager.js:249-251). `stopCapturing()` sets `lastChange=0` (UndoManager.js:341). Time source is `time.getUnixTime()` (ms). `captureTimeout=Infinity` never splits (test `testInfiniteCaptureTimeout`); `0` never merges (`now - lastChange < 0` false). Needs injectable clock in port.
- **UM-04 Events.** `stack-item-added` for new item, `stack-item-updated` for merge, payload `{stackItem, origin: transaction.origin, type: undoing?'redo':'undo', changedParentTypes}` (UndoManager.js:259-266). Note `type` is `'redo'` when the stack being filled is the redo stack, i.e. while undoing. Test: `testUndoEvents`.
- **UM-05 Redo-stack invalidation.** A tracked user change (neither undoing nor redoing) calls `clear(false, true)` (UndoManager.js:227). During undo, `stopCapturing()` is called so the next undo is separate (UndoManager.js:224). Test: `testUndoText`, `testDoubleUndo`.
- **UM-06 StackItem contents.** `insertions` = delete-set of ranges `[beforeState, afterState)` per client; `deletions` = `transaction.deleteSet` (UndoManager.js:229-247). `meta` is a Map for user data surviving into `stack-item-popped`. Note it stores `transaction.deleteSet` by reference for a new item (UndoManager.js:246).
- **UM-07 Keep flag.** After capture, every deleted `Item` within scope gets `keepItem(item, true)` (parents too) so GC cannot remove its content (UndoManager.js:253-257, Item.js:68-73). `clear()` reverses it with `keepItem(item,false)` (UndoManager.js:40-46). Interplay with GC is GC-05.
- **UM-08 `undo()/redo()`** set `undoing/redoing` for the duration (try/finally) and return the popped `StackItem` or `null` (UndoManager.js:349-374). `canUndo/canRedo` = stack non-empty. Transaction origin of the undo is the UndoManager itself (`transact(doc, fn, undoManager)`, UndoManager.js:120).
- **UM-09 Pop loop skips no-op stack items.** `while (stack.length>0 && currStackItem===null)`: pops items until one performs a change (UndoManager.js:63, 111). Test: `testUndoUntilChangePerformed`.
- **UM-10 Undo algorithm.** (a) insertions in scope that are not yet deleted are deleted, following `redone` chains via `followRedone` and splitting with `getItemCleanStart` (UndoManager.js:75-88); deletions happen in reverse order, gated by `deleteFilter` (UndoManager.js:104-110). (b) deletions in scope not themselves in `insertions` are redone via `redoItem` (UndoManager.js:89-101). Redo of an item whose parent was deleted tries to redo the parent first (Item.js:161-165). Test: `testUndoDeleteFilter`, `testUndoNestedUndoIssue`, `testConsecutiveRedoBug`, `testUndoBlockBug`, `testSpecialDeletionCase`.
- **UM-11 Redo bookkeeping.** `item.redone = newId` is set on the original and the new item is `keepItem(true)` (Item.js:241-242). Splits propagate `redone` with offset (Item.js:104-106); `mergeWith` refuses items with `redone !== null` (Item.js:580-581). `redone` is NOT sent over the wire.
- **UM-12 Map-key semantics.** Redoing a map entry returns null (no change) if a newer remote value exists, unless `ignoreRemoteMapChanges` (Item.js:207-222); cross-parent left is dropped (#757, Item.js:226-229). Test: `testBehaviorOfIgnoreremotemapchangesProperty`, `testUndoDeleteInMap`, `testUndoSetAttributeAndDeleteSyncsAttributes`.
- **UM-13 Search markers cleared** for any type with a `null`-key change after pop (UndoManager.js:113-118). Implementation detail, relevant to YText/YArray caches only.
- **UM-14 `stack-item-popped`** emitted after the transaction, payload `{stackItem, type, changedParentTypes, origin: undoManager}`; `currStackItem` is set during the transaction so observers can see `undoManager.currStackItem` (UndoManager.js:121-126). Test: `testUndoDoingStackItem`.
- **UM-15 `clear(undo=true, redo=true)`** acts only if the selected stack non-empty; runs in a transaction, un-keeps items, resets arrays, emits `stack-cleared {undoStackCleared, redoStackCleared}` with the REQUESTED flags (not whether each was non-empty) (UndoManager.js:304-318). Edge: `clear()` inside a user change (UM-05) goes through `doc.transact` while already in `afterTransaction`.
- **UM-16 Scope management.** `addToScope` dedupes by identity and logs `[yjs#509] Not same Y.Doc` for foreign docs but still adds them (UndoManager.js:278-288). `addTrackedOrigin/removeTrackedOrigin` mutate the set (UndoManager.js:293-302).
- **UM-17 Lifecycle.** Subscribes to `afterTransaction` and `destroy` on the doc; `destroy()` unsubscribes and calls ObservableV2.destroy (UndoManager.js:268-271, 394-399). Binds `this.destroy` in the constructor.
- **UM-18 Deleted-type content.** Deleting then undoing a nested type recreates the type via `ContentType.copy`; embedded types, XML and formatting have regression tests: `testUndoInEmbed`, `testUndoXml`, `testUndoXmlBug`, `testUndoDeleteTextFormat`, `testInconsistentFormat`.
- **UM-19 Subdocs.** Undo/redo of a subdoc item works and leaves array length 1 (SUB-10). Test: doc.tests.js `testSubdocsUndo`.
- **UM-20 Remote-edit interaction.** Remote inserts inside an undone range remain (undo deletes only captured insertions). Test: `testUndoText`, `testUndoMap`, `testUndoArray` with multi-client fixtures from `testHelper.init`.

Edge cases worth dedicated cases: stack item whose items were all remotely deleted (popStackItem returns null, UM-09); `captureTransaction` returning false; undo with `trackedOrigins` containing a class (constructor match); scope = Doc vs scope = type; `deleteFilter` returning false for parents but true for children; `gc: true` doc (default) vs `gc:false` (keep flag makes both work).

## 4. Snapshot (`utils/Snapshot.js`)

- **SNAP-01 Shape.** `Snapshot{ds: DeleteSet, sv: Map<client,clock>}` (Snapshot.js:28-44). `snapshot(doc)` = `createDeleteSetFromStructStore(store)` + `getStateVector(store)` (Snapshot.js:125). The delete set is rebuilt from structs, so GC structs count as deleted (utils/DeleteSet.js:188-213, merges adjacent deleted structs into runs).
- **SNAP-02 Wire format.** V1: `writeDeleteSet` then `writeStateVector` using DSEncoderV1; V2 identical with DSEncoderV2 (Snapshot.js:85-110). Order is DS first, SV second (opposite of update messages). Round-trip tests plus byte fixtures vs the oracle for both versions.
- **SNAP-03 `equalSnapshots`** (Snapshot.js:51-78): false on different SV size or DS client count; compares SV by lookup; DS compared per client by `(clock,len)` list in order (missing client treated as empty array, so a client present in ds1 with empty list is equal only if lengths match). Note: no normalization (sort/merge) is done, so two semantically-equal but unmerged DS compare unequal; document in the port.
- **SNAP-04 `emptySnapshot`** is a shared mutable module singleton (Snapshot.js:119). **[DIVERGENCE?]** C# should expose it as immutable or fresh-per-access; tests should assert content only.
- **SNAP-05 `isVisible(item, snapshot)`.** No snapshot: `!item.deleted`. With snapshot: client present in `sv`, `sv[client] > item.clock`, and not in snapshot ds (Snapshot.js:134-136). Used by Array/Map "snapshot" readers (`types/AbstractType.js:481, 600, 944, 968`) and YText.toDelta (`types/YText.js:1044-1085`). Test: `testBasic*`, `testDeletedItemsBase`, `testDeletedItems2`, `testDependentChanges`.
- **SNAP-06 `splitSnapshotAffectedStructs`** splits items at snapshot clock boundaries inside the current transaction, memoized per snapshot in `transaction.meta` keyed by the function itself (Snapshot.js:142-155). It runs inside `toDelta` with origin `'cleanup'` (YText.js:1096-1108), so structs are merged again after (the transaction origin is `'cleanup'`; splits alone produce no update event).
- **SNAP-07 `toDelta(snapshot, prevSnapshot, computeYChange)`** produces `ychange {type:'added'|'removed'}` attributes (default object, or user computeYChange(type, id)) (YText.js:1044-1060). Inferred edge: snapshot given without prevSnapshot marks items not visible as `removed`.
- **SNAP-08 `createDocFromSnapshot(origin, snap, newDoc=new Doc())`.** Throws `Garbage-collection must be disabled in \`originDoc\`!` if `originDoc.gc` (Snapshot.js:172-174). Writes a V2 update by hand: client count (clients with `clock>0` only), per client struct count, client, start clock 0, every struct up to `clock-1`; splits at the snapshot boundary first (Snapshot.js:178-207); then writes the snapshot's DS; applies with origin `'snapshot'` (Snapshot.js:209). Edge: clients in the snapshot SV but absent from the origin store yield `structs=[]` and `findIndexSS([],..)` behaviour is undefined (inferred); `clock === 0` skipped. Items created by clients not in `sv` are omitted entirely. Test: `testBasicRestoreSnapshot`, `testEmptyRestoreSnapshot`, `testRestoreSnapshotWithSubType`, `testRestoreDeletedItem1`, `testRestoreLeftItem`.
- **SNAP-09 Side effect.** `createDocFromSnapshot` runs a transaction on the origin doc that splits structs (`getItemCleanStart`), so `originDoc.store` struct counts can change; state vectors and content do not. Test the invariant, not struct counts.
- **SNAP-10 `snapshotContainsUpdate(V2)`** (Snapshot.js:218-236): false as soon as any struct end exceeds `sv[client]`; then merges the update's DS into the snapshot's and requires `equalDeleteSets`. Uses `LazyStructReader(decoder, false)` i.e. does not filter Skip structs (a Skip beyond sv returns false). V1 wrapper at Snapshot.js:236. Test: `testContainsUpdate`, `testContainsUpdate2` (#767).
- **SNAP-11 GC interplay.** Snapshots of a `gc=true` doc work for state vector/ds but readers return missing content for GC'd items (items become `ContentDeleted`, Item.js:642), so snapshot reads are only meaningful on `gc:false` docs; the test suite always uses `gc:false` (tests/snapshot.tests.js:9, 21, 36...; `doc0.gc=false` at 178-179 toggles the flag at runtime, which is allowed because gc is read each cleanup, Transaction.js:327).

## 5. RelativePosition (`utils/RelativePosition.js`)

- **RP-01 Shape.** `RelativePosition{type: ID|null, tname: string|null, item: ID|null, assoc: number}` (RelativePosition.js:43-76). Exactly one of item / tname / type is the anchor (the others null).
- **RP-02 Creation from index** `createRelativePositionFromTypeIndex(type, index, assoc=0)` (RelativePosition.js:163-187):
  - `assoc>=0`: anchor on the item containing `index`; past end -> `item=null` (end of type).
  - `assoc<0`: `index===0` -> `item=null` (start-of-type marker); else `index--`, anchor on the char to the left; if the walk reaches the last struct with remaining index, returns `t.lastId` of the last item **including deleted/uncountable trailing items** (line 180-183).
  - Skips deleted and non-countable (format) items while counting.
  - Test: all `testRelativePositionCase1-7`, `testRelativePositionAssociationDifference`.
- **RP-03 Type anchoring** `createRelativePosition(type,item,assoc)`: root type -> `tname = findRootTypeKey(type)` (throws `unexpectedCase` if type not in `doc.share`, utils/ID.js:81-89), nested type -> `type = ID of its _item` (RelativePosition.js:142-151).
- **RP-04 Binary encoding.** Tag byte: `0` + ID (item), `1` + varstring (tname), `2` + ID (type); then `varInt assoc` (RelativePosition.js:195-213). Writing with all three null throws `unexpectedCase`. Decoding: assoc is optional (absent -> 0, `hasContent` check, line 249) for backward compat; an unknown tag yields an all-null position (switch has no default, line 235-248), which then throws on re-encode. Byte fixtures for each tag and with/without assoc.
- **RP-05 JSON.** `relativePositionToJSON` emits `type`/`tname`/`item` only if truthy and `assoc` if non-null (RelativePosition.js:82-97); `createRelativePositionFromJSON` defaults `assoc` to 0 and null-coalesces `tname` (line 105). **Quirk [DIVERGENCE?]:** the root text/array created with the default name `''` has `tname=''`, which is falsy, so JSON drops it; the reconstructed position then has all three anchors null and cannot be encoded/resolved (`unexpectedCase`). Test the quirk, record a decision whether to keep it.
- **RP-06 Resolution** `createAbsolutePositionFromRelativePosition(rpos, doc, followUndoneDeletions=true)` (RelativePosition.js:289-342):
  - item anchor: returns `null` if the client's state `<= clock` (unknown item), or the resolved struct is not an `Item` (GC'd); `followUndoneDeletions` uses `followRedone` else `getItemWithOffset` (lines 298-305).
  - index = (left-count of live countable items) + (`diff` + (assoc>=0 ? 0 : 1)) if the anchor item is alive and countable, else just the left count with 0 offset (line 308-315).
  - if the parent type's own item is deleted, index stays `0` and a position is still returned (line 307). Inferred: callers get `(deletedType, 0)`.
  - tname anchor: `doc.get(tname)` — **creates** a generic type if absent (side effect) (line 319).
  - type-id anchor: `null` if state unknown or item GC'd/not a ContentType (lines 321-331).
  - End/start: `assoc>=0` -> `type._length`; `assoc<0` -> `0` (lines 335-339).
  - `AbsolutePosition.assoc` echoes `rpos.assoc`.
  - Tests: `checkRelativePositions` helper (round trip all indexes x assoc -1,0,1), `testRelativePositionCase7` (#657), `testRelativePositionWithUndo` (#638: follow=true gives 1 after undo locally; follow=false or a remote clone gives 6).
- **RP-07 `compareRelativePositions(a,b)`**: identity, or both non-null with equal `tname`, `item`, `type` (via `compareIDs`) and `assoc` (RelativePosition.js:351-353). Null/null: `a===b` true; null vs value false.
- **RP-08 Cross-client determinism.** With `followUndoneDeletions=true` results may differ between replicas (documented in the source comment, RelativePosition.js:271-281). Differential tests must use `false` when comparing replicas.
- **RP-09 Concurrent edits.** Positions follow content through inserts before/after, deletions of the anchor char (-> index of nearest live right neighbour, offset 0) and splits/merges of items (structure-independent because anchoring is by ID). Add scenarios: delete anchor, delete whole range, insert at anchor with each assoc, tname anchored on empty type, nested type anchored, anchor in a GC'd region (-> `null`).

## 6. PermanentUserData (`utils/PermanentUserData.js`)

Test: `tests/encoding.tests.js:46-80` (`testPermanentUserData`), the only oracle coverage.

- **PUD-01 Storage layout.** Default store is `doc.getMap('users')` (PermanentUserData.js:19). Per user description a `YMap{ids: YArray<number>, ds: YArray<Uint8Array>}` (PermanentUserData.js:77-84). Each `ds` entry is a V1-encoded DeleteSet (`DSEncoderV1`, line 99-103/113-114).
- **PUD-02 Construction** rebuilds in-memory maps from existing data: `clients` (clientID -> description) from `ids`, `dss` (description -> merged DeleteSet) from `ds` (lines 37-58), and subscribes to additions for both arrays and to new users on the map (lines 44-64). Non-`Uint8Array` entries in `ds` are ignored in the observer (line 47) but not filtered in the initial `ds.map(...)` read (line 53) (inferred crash risk).
- **PUD-03 `setUserMapping(doc, clientid, description, {filter})`.** Creates the user entry if missing, pushes `clientid` to `ids` (lines 77-85). Registers an `afterTransaction` listener on `doc`; on each **local** transaction with a non-empty delete set that passes `filter(tr, ds)`, it pushes the encoded DS to `ds` — deferred with `setTimeout(...)` i.e. asynchronous (lines 108-118). **Port note:** needs an injectable scheduler (or flush hook) so tests are deterministic; the oracle test awaits `promise.wait(10)`.
- **PUD-04 Overwritten user entries.** An `observe` on `users` re-checks asynchronously (`setTimeout 0`); if the user map entry was replaced (concurrent creation), the new object receives all known `ids` and the merged `ds` (lines 86-106). Test: `testPermanentUserData` third doc with same description.
- **PUD-05 Each `setUserMapping` call adds new listeners that are never removed** (lines 86, 108). Behaviour to preserve: two calls double-record deletions. **[DIVERGENCE?]** Memory leak; ADR needed if fixed.
- **PUD-06 Lookups.** `getUserByClientId(id)` returns description or `null` (line 126); `getUserByDeletedId(id)` scans `dss` in insertion order and returns the first description whose DS contains `id`, else `null` (lines 133-140). Test: used in `testPermanentUserData` (lines 70-80).
- **PUD-07 Key deletion edge.** `storeType.observe` runs `initUser(storeType.get(key), key)` for every changed key; if a key was deleted `get` returns `undefined` and `initUser` dereferences it (lines 60-63, `user.get('ds')`). Inferred crash; per ADR 0003 "crashes always diverge".
- **PUD-08 Remote delete sets** received later merge into `dss[description]` via `mergeDeleteSets` (line 48), and ids append into `clients` (line 55).
- **PUD-09 Clientid reuse.** `clients` map overwrites on duplicate clientid across users (last write wins; inferred).

## 7. Garbage collection (`structs/Item.js`, `structs/GC.js`, `structs/ContentDeleted.js`, `utils/Transaction.js`)

- **GC-01 Flag and filter.** `doc.gc` (default true) and `gcFilter(item)` (default accept-all) are checked per cleanup: `if (doc.gc) tryGcDeleteSet(ds, store, doc.gcFilter)` (Transaction.js:327-329). `gc` is a plain mutable field and can be flipped at runtime (tests: snapshot.tests.js:178, y-text.tests.js:1877, 1919).
- **GC-02 Scope.** Only structs in the **current transaction's delete set** are examined (Transaction.js:199-220). Items deleted while `gc=false` are never retroactively collected when `gc` becomes true (inferred from scan scope). `Y.tryGc` is exported for manual use (Transaction.js:251).
- **GC-03 Eligibility.** `struct instanceof Item && struct.deleted && !struct.keep && gcFilter(struct)` (Transaction.js:214). `keep` is runtime only (Item.js:62-63): not serialized, propagated to split-right (Item.js:101) and merge-left (Item.js:598).
- **GC-04 Collection forms.** `Item.gc(store, parentGCd)` (Item.js:634-644): calls `content.gc(store)`, then if `parentGCd` replaces the struct with a `GC(id,length)` struct, otherwise replaces content with `ContentDeleted(length)`. Top-level deleted items keep their `Item` shell (with `ContentDeleted`); children of a deleted type (via `ContentType.gc`, ContentType.js:128-142) become bare `GC` structs, and the type's `_start`/`_map` are cleared. Throws `unexpectedCase` if called on a non-deleted item (Item.js:635-637).
- **GC-05 Undo keep.** UndoManager marks scope deletions `keep=true` so GC skips them (UM-07). After `clear()` they become collectable at the next deletion transaction touching them only (since GC scans only the current delete set, GC-02): inferred edge, items un-kept by `clear()` are not collected until redeleted. Candidate behaviour test.
- **GC-06 Wire effects.** `GC` structs encode as ref 0 + length (GC.js:44-47); `ContentDeleted` as ref 1 + length (structs/ContentDeleted.js). Same logical document encodes differently with gc on/off: `encodeStateAsUpdate` byte differences between `gc:true` and `gc:false` docs are expected and must match the oracle. Merging of adjacent GC/deleted structs happens in `tryMergeDeleteSet` regardless of the `gc` flag (Transaction.js:330).
- **GC-07 Integration of orphans.** An incoming Item whose parent is a GC struct or whose origin is GC gets `parent=null` and is integrated as a GC struct instead (Item.js:392-396, 529-531). So a `gc=true` replica receiving concurrent children of a type that it already collected silently discards them while a `gc=false` replica keeps them hidden: convergence of *visible* state is expected, byte-for-byte state differs.
- **GC-08 Merge.** After every transaction deleted/GC structs are merged where `left.deleted===right.deleted && same constructor && mergeWith` (Transaction.js:171-192, 330-359); items with differing `redone`/`keep` constraints follow Item.mergeWith rules (Item.js:571-609). Struct counts are observable via `doc.store.clients`, so tests should assert them only through the public API; a "stats" hook may be needed.
- **GC-09 Subdocs.** `ContentDoc.gc` is a no-op (SUB-09); `Doc.gc=false` is persisted per subdoc through opts (SUB-02).
- **GC-10 Snapshots.** `createDocFromSnapshot` requires `gc=false` (SNAP-08); toggling `gc=false` after content is collected does not restore it.
- **GC-11 Test helper.** The oracle fuzz `compare` helper (tests/testHelper.js:298-330) checks convergence with `gc` on, ; most `*.tests.js` run with default gc=true, so GC-on is the *default* coverage and GC-off coverage is explicit (`snapshot`, `undo-redo` with `gc:false`, `updates`).

## 8. Cross-cutting scenarios for the suite

1. Matrix gc in {true,false} x features {undo, snapshot, relative position, subdoc, update V1/V2}.
2. Replica convergence + byte equality of `encodeStateAsUpdate` for each gc setting (bytes differ between settings; each must match the oracle).
3. Event ordering log across `beforeAllTransactions ... afterAllTransactions` with a nested-transaction observer (DOC-09).
4. Deterministic clock/RNG/scheduler seams needed: client id (DOC-11), uuid (DOC-01), `getUnixTime` (UM-03), `setTimeout` (PUD-03/04). Surface this to TASK-1.14 (API contract).
5. Edge inputs: empty doc snapshot/relative position, `''` type name, positions at index 0/length/past-length, destroyed doc operations, double `destroy`, duplicate subdoc guids, undo with zero stack, redo after new change.
